## 开发准备

<div className="fd-steps [&_h3]:fd-step">

### 在仓库根目录开发

请在编辑器中打开主题仓库，并从仓库根目录执行下面的命令。仓库使用 pnpm `11.20.0` 和 Node.js 24.x。

### 安装依赖

```bash
pnpm install --frozen-lockfile
```

该命令会安装主题、本地 Hexo 演示站 `dev/site` 和文档工作区所需的依赖。

### 启用主题开发模式

如果要在 Hexo 站点中使用主题源代码，请在站点的 `_config.redefine.yml` 中将 `developer.enable` 设置为 `true`。本地演示站将此设置保存在 `dev/site/_config.dev.yml` 中，`pnpm dev` 会自动加载该文件。

```yaml
developer:
  enable: true
```

### 启动本地演示站

```bash
pnpm dev
```

该命令会清理演示站生成的状态，将当前主题源代码链接到 `dev/site/themes/redefine`，在 `http://127.0.0.1:4000` 启动 Hexo，并同时监听浏览器端 JavaScript 和 CSS。esbuild 会在 `source/js/build/dev/` 下生成带 source map 的未压缩开发 bundle，Tailwind 则重新编译 `styles/theme.css`。修改 JavaScript 后需要手动刷新浏览器；开发命令不提供实时重载。

开发入口固定为 `source/js/build/dev/main.js`，拆分的 chunk 使用 `chunks/[name]-[hash].js` 命名，避免多个共享 chunk 的文件名冲突。

</div>

## 演示站与部署模式

`dev/site/` 是 Redefine 的规范演示站来源，用于本地开发、PR 预览、分支预览和生产演示站。演示文章、页面和站点配置都应放在这里；`dev/site/themes/redefine/` 下的生成链接以及 `dev/site/public/` 输出仅属于本地或 CI 状态。

`dev/site/_config.yml` 保存 Hexo 站点设置，`dev/site/_config.redefine.yml` 只保存演示站有意覆盖的主题设置，`dev/site/_config.dev.yml` 只保存本地开发模式覆盖。测试专用配置位于 `tests/fixtures/`。

本地执行 `pnpm dev` 时会启用主题开发模式，并使用当前检出的主题资源。CI 在生成所有部署站点前都会关闭开发模式。PR 和分支预览使用当前检出的资源并关闭 CDN；生产演示站则保留配置中的版本化 CDN 行为。

## 构建与清理

请在仓库根目录执行以下命令：

```bash
pnpm clean
pnpm build
pnpm test
pnpm check
```

- `pnpm clean` 删除根工作区拥有的全部主题生成资源和演示站状态。
- `pnpm build` 生成全部生产环境 CSS 和浏览器端 JavaScript。
- `pnpm test` 运行 Node.js 测试套件及其生成站点覆盖。
- `pnpm check` 是提交 PR 前的规范主题验证命令，会依次运行测试和生产构建。

CSS 和 JavaScript 的监听均由 `pnpm dev` 负责，因此这里不单独记录监听命令或构建辅助命令。

请勿直接修改构建输出。核心和插件 CSS 位于 `source/css/build/`，JavaScript 位于 `source/js/build/`；这些目录由本地开发或 CI 生成且不会提交到 Git，应当修改对应的源文件。`source/assets/` 下的运行时资源仍然会提交到仓库。

代码高亮主题只加载配置选中的浅色和深色资源；评论样式只加载已启用且受支持的评论系统资源；APlayer 样式仅在启用 APlayer 时加载。因此，这些可选样式保留在 `source/css/build/plugins/` 中，不会全部合并到核心 CSS。Number Flow 是应用依赖，由构建生成按需加载的 JavaScript chunk，并在启用页脚运行时间或工具栏阅读百分比时加载。

主题样式管线不再包含 Stylus，演示站也已移除 `hexo-renderer-stylus`。发布包包含运行时所需的原生 CSS 和 Tailwind 构建结果，使用主题的 Hexo 站点无需安装样式表渲染器。

### 可选脚本加载

`source/js/main.js` 在首次打开页面和每次 Swup 页面切换后，根据功能配置和当前 DOM 按需加载功能模块及其依赖。新增可选功能时，应复用这个页面初始化流程，并在异步加载完成后检查页面取消信号。

| 依赖        | 加载条件                                       |
| ----------- | ---------------------------------------------- |
| Moment      | 当前页面存在说说日期                           |
| Typed       | 启用了副标题动画，且当前页面存在副标题容器     |
| Mermaid     | 启用了 Mermaid，且当前页面存在图表             |
| MiniMasonry | 当前页面存在相册容器                           |
| Pangu       | 启用了中英文间距处理，且当前页面存在正文       |
| 评论 SDK    | 当前页面启用了评论，且评论区接近可视区域       |
| EXIF 解析器 | 读者首次打开图片的 EXIF 信息面板               |
| APlayer     | 启用了播放器、配置了音频条目，且存在播放器容器 |

ES 模块使用动态 `import()`；需要全局变量的第三方脚本使用共享的 `loadScriptOnce()`。加载函数按 URL 缓存 Promise，复用进行中或已完成的加载，失败后清除缓存以允许重试。脚本地址仍通过主题资源解析逻辑生成，保持开发模式、生产构建、子路径部署和 CDN 配置一致。

Waline、Gitalk、Twikoo、Giscus、Utterances 和 Artalk 共用评论加载控制器。Giscus 和 Utterances 的引导脚本需要为每个新容器执行一次，不能按全局 SDK 去重；下载仍可利用浏览器 HTTP 缓存。页面配置中的 `0`、`false` 和指定 Issue 编号应原样传递，避免使用 `||` 默认值覆盖有效设置。

库的加载结果可以跨页面复用，组件实例和观察器则属于当前页面。页面替换前应清理观察器和事件处理器，并取消旧页面的初始化；不要因为一个页面离开而中断其他页面可能继续使用的共享脚本加载。避免只依靠 EJS 页面条件输出脚本，否则直接打开其他页面后再通过 Swup 跳转时，目标页面可能缺少依赖。

评论控制器在页面替换前销毁 Waline、Artalk 等提供销毁接口的实例。明暗模式通过事件更新已挂载的实例或 iframe，无需轮询等待组件出现。APlayer 属于全站实例，加载后跨 Swup 页面切换保留，并将音频预加载设为 `none`。启用了对应功能时，Swup 和预加载动画所需的初始依赖仍正常加载。

说说模板在构建时输出可读的 `<time>` 内容，Moment 加载后再根据 `datetime` 格式化日期。评论控制器使用 `IntersectionObserver` 提前加载评论，浏览器不支持时直接加载，并提供加载状态与失败重试；Giscus 的 `loading: eager` 设置仍会立即加载。验证改动时，应覆盖直接打开、站内跳转、前进后退、加载期间快速切页、配色切换和失败后重试。

## 预览发布说明

版本号更新和 Git 标签创建仍由维护者手动完成。在推送匹配版本的标签前，可以使用下列命令生成并检查双语发布说明：

```bash
RELEASE_LLM_URL=... RELEASE_LLM_KEY=... pnpm release:notes -- v2.10.0
pnpm release:notes:check
```

目标标签可以暂时不存在。命令只会在仓库根目录生成被 Git 忽略的 `release-notes.md`，不会发布 NPM 或 CDN 资源，也不会创建 GitHub Release。确认内容后再推送匹配的版本标签；CI 会先构建主题，再创建 GitHub Release。如果 OpenCode 不可用或生成内容未通过检查，CI 会改用 GitHub 自动生成的说明。

## 项目结构

- `styles/theme.css`：核心原生 CSS 和 Tailwind 入口，按明确顺序导入主题样式。
- `styles/base/`：CSS 变量、全局规则、动画和渲染内容的基础样式。
- `styles/components/`：需要复杂选择器或无法仅在模板中表达的主题组件样式。
- `styles/plugins/`：代码高亮主题、评论系统和 APlayer 等独立可选样式。
- `source/css/build/`：构建生成的核心 CSS 和插件 CSS；请勿直接修改。
- `source/assets/`：提交到仓库的运行时资源。
- `source/js/`：浏览器端 JavaScript 源代码。
- `scripts/`：Hexo 生成阶段使用的 Node 脚本。
- `layout/`：Hexo 模板。Hexo 必需的入口文件保留在根目录，可复用的渲染片段位于
  `layout/components/`，路由专属标记位于 `layout/pages/`；仅评论、首页和文章等包含
  多个紧密相关文件的模块使用子目录。
- `dev/site/`：本地演示站的配置、文章、页面和测试内容。

## 自定义主题

主题控制的 EJS 或脚本生成标记应使用 Tailwind 工具类处理普通布局和外观；重复界面应提取到模板或辅助函数。间距和圆角直接使用 Tailwind 默认比例，不要定义主题专用替代比例。页面分发集中并显式写在 `layout/pages/router.ejs` 中，自定义页面通过已记录的 `template` Front Matter 选择。全局规则、渲染内容、复杂选择器和第三方标记由 `styles/base/`、`styles/components/` 或 `styles/plugins/` 中的原生 CSS 负责。新增原生 CSS 文件后，还需要从 `styles/theme.css` 或相应入口显式导入。

### 使用规范的编号颜色基础

- `--rd-background-100` 和 `--rd-background-200` 分别用于主要和交替页面背景。
- `--rd-gray-100`、`--rd-gray-200`、`--rd-gray-300` 分别用于组件的默认、悬停和激活背景。
- `--rd-gray-400`、`--rd-gray-500`、`--rd-gray-600` 分别用于组件的默认、悬停和激活边框。
- `--rd-gray-700`、`--rd-gray-800` 分别用于高对比度组件的默认和悬停背景。
- `--rd-gray-900` 用于次要文字和图标，`--rd-gray-1000` 用于主要文字和图标。
- `--rd-gray-alpha-100` 至 `--rd-gray-alpha-1000` 在需要透明度时与同编号的纯色灰阶用途一致；`--rd-gray-alpha-400` 仍用于标准结构边框和分隔线。
- `--rd-primary-text` 用于主题色填充上的文字和图标。
- `--rd-shadow` 继续表示完整的明暗模式阴影效果。

不要新增 `card`、`foreground` 等组件别名，组件应直接选择与职责匹配的编号变量。引用明暗模式变量或配置生成变量的 Tailwind 运行时映射必须放在 `@theme inline` 中。

详细的 Tailwind CSS 文档请参考 [Tailwind CSS 官方文档](https://tailwindcss.com/docs)。
